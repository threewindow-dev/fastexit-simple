# 개념 모델 (Conceptual Data Model) - fastexit

**목적**: fastexit 시스템의 핵심 비즈니스 개념과 그 관계를 정의합니다.

**작성일**: 2026-01-22

**소유자**: Product Owner, Development Team

---

## 개요

이 문서는 데이터베이스 설계 이전 단계에서 비즈니스 요구사항과 도메인 개념을 명확히 정의합니다. 구현 기술과 독립적이며, 도메인 전문가와 개발자가 공유하는 유비쿼터스 언어(Ubiquitous Language)를 사용합니다.

---

## 핵심 엔티티

### 사용자 (User)

**개념**: 시스템을 사용하는 사람. 관리자 또는 일반 사용자로 구분됨

**식별자**: 사용자 ID (시스템 생성)

**주요 속성**:
- 사용자명 (username): 고유 로그인 ID
- 이메일 (email): 고유 이메일 주소
- 역할 (role): admin (관리자) | user (일반 사용자)

**불변식**:
- 사용자명은 고유해야 함
- 이메일은 고유해야 함
- 역할은 필수

**생명주기**: 회원가입 시 생성, 첫 번째 가입자는 자동으로 admin 역할 부여

---

### 금융사 (Institution)

**개념**: 사용자의 자산을 보관하고 관리하는 금융기관

**식별자**: 금융사 ID (시스템 생성)

**주요 속성**:
- 금융사명 (name): 표시명 (예: "삼성증권", "KB증권")
- 금융사 유형 (type): 증권사, 은행, 기타

**불변식**:
- 금융사명은 필수

**생명주기**: 시스템 설정 시 등록, 변경 드묾

---

### 계좌 (Account)

**개념**: 금융사 내에서 자산을 관리하는 논리적 단위

**식별자**: 계좌 ID (시스템 생성)

**주요 속성**:
- 계좌명 (name): 사용자 정의 이름 (예: "ISA 계좌", "연금저축")
- 계좌 유형 (type): ISA, CMA, 일반 증권, 예금 등
- 잔액 (balance): 현재 총 평가액 (계산 속성)

**불변식**:
- 계좌는 반드시 하나의 금융사에 속해야 함

**생명주기**: 관리자가 등록, 수정, 삭제 가능

---

### 계좌 그룹 (Account Group)

**개념**: 관리자가 정의한 논리적 계좌 그룹핑. 서로 다른 금융사의 계좌를 하나의 그룹으로 관리

**식별자**: 그룹 ID (시스템 생성)

**주요 속성**:
- 그룹명 (name): 사용자 정의 이름 (예: "미국 투자 계좌", "장기 저축")
- 포함 계좌 목록 (accounts): 1개 이상의 계좌
- 그룹 총액 (group_total): 포함된 모든 계좌의 잔액 합계 (계산 속성)

**관계**:
```
[AccountGroup] 1 ────────── * [Account]
```

**불변식**:
- 그룹명은 필수
- 그룹은 0개 이상의 계좌를 포함 가능
- 하나의 계좌는 여러 그룹에 포함될 수 있음 (M:N 관계)
- 같은 금융사 계좌와 다른 금융사 계좌를 함께 그룹화 가능

**생명주기**: 관리자가 생성, 수정, 삭제 가능

**용도**: 사용자가 논리적으로 관련된 계좌들을 함께 조회/비교하기 위함

---

### 자산군 (Asset Class)

**개념**: 금융상품을 분류하는 상위 카테고리

**예시**: 주식, 채권, 통화, 금, 부동산, 가상자산, 기타자산

**용도**: 포트폴리오 자산의 큰 분류 단위로 사용

**특징**:
- 사전 정의된 카테고리 (시스템 제공)
- 변경 불가
- 각 상품은 하나의 자산군에만 속함

---

### 상품 (Product)

**개념**: 투자 가능한 금융상품의 마스터 데이터. 자산군과 분류 속성을 보유하며, 계좌에 편입될 때 자산(Holding)과 연결됨

**예시**: VOO (S&P500 ETF), TLT (20+ Year Treasury ETF), AAPL (Apple 주식), 달러, 금현물, O (Realty Income), BITO (Bitcoin ETF), 청약저축, 현금, 정기예금, RP, 발행어음 등

**식별자**: 상품 ID (시스템 생성)

**주요 속성**:
- 상품명 (product_name)
- 자산군 (asset_class): 주식, 채권, 통화, 금, 부동산, 가상자산, 기타자산
- 자산 속성 (attributes):
  - 지역 (region): 대한민국, 미국
  - 통화 (currency): 원화, 달러
  - 투자유형 (investment_type): 직접, ETF
  - 자산특징 (characteristics): 개별종목, 수시입출금, 지수추종, 월배당, 소수점투자, 현물, 레버리지, 예금, 적금
  - 위험도 (risk_level): 위험, 안전

**특징**:
- 마스터 데이터로 중앙 관리
- 모든 보유 자산은 반드시 기존 상품을 참조 (또는 등록 후 참조)
- 상품의 분류/속성 변경은 이력 관리가 필요 (과거 스냅샷과 불일치 방지)

**자산군과의 관계**:
- VOO, TLT → 자산군: 주식
- AAPL → 자산군: 주식
- 달러, RP, 발행어음, 정기예금 → 자산군: 통화/채권/예금(정의에 따라 매핑)
- 금현물 → 자산군: 금
- BITO → 자산군: 가상자산
- 청약저축 → 자산군: 기타자산

---

### 자산 (Holding)

**개념**: 특정 계좌에서 보유 중인 개별 금융상품

**식별자**: 자산 ID (시스템 생성)

**주요 속성**:
- 상품 (product): Product 참조
- 평가금액: 스냅샷/자산 현황에서만 관리 (Holding에는 저장하지 않음)

**불변식**:
- 자산은 반드시 하나의 계좌에 속해야 함
- 자산은 반드시 하나의 상품(Product)을 참조해야 함

**생명주기**: 관리자가 추가, 수정, 삭제 가능

**삭제 정책 (Two-step Deletion)**:
- 1단계: 숨김(Hide) — 관리자가 아닌 사용자에게 보이지 않도록 처리
  - 필드 예: `is_visible = false` 또는 `hidden_at` 타임스탬프
  - 효과: 조회, 합계, 보고서에서 제외되지만 데이터는 유지
  - 스냅샷: 과거 스냅샷에는 여전히 포함(당시 상태의 불변 기록)
- 2단계: 완전 삭제(Hard Delete) — 자산 레코드 영구 삭제
  - 필드 예: `deleted_at` 기록 후 물리 삭제 수행(or 소프트 삭제 유지 정책 선택)
  - 제약: 관리자 권한 필요, 이미 생성된 스냅샷 데이터는 불변 유지
  - 감사: 삭제 사유와 수행자 기록 권장

---

## 관계 (Relationships)

### 금융사 ─ 계좌

```
[Institution] 1 ────────── * [Account]
```

- **다중도**: 1:N (금융사 하나당 여러 계좌)
- **관계 유형**: 포함 (Composition)
- **비즈니스 규칙**:
  - 금융사는 0개 이상의 계좌를 가질 수 있음
  - 계좌는 정확히 하나의 금융사에 속해야 함
  - 금융사가 삭제되면 해당 계좌도 삭제되어야 함 (Cascade)

---

### 계좌 ─ 자산

```
[Account] 1 ────────── * [Holding]
```

- **다중도**: 1:N (계좌 하나당 여러 자산)
- **관계 유형**: 포함 (Composition)
- **비즈니스 규칙**:
  - 계좌는 0개 이상의 자산을 보유할 수 있음
  - 자산은 정확히 하나의 계좌에 속해야 함
  - 계좌가 삭제되면 해당 자산도 삭제되어야 함 (Cascade)
  - 계좌의 잔액은 모든 자산의 평가금액 합계

---

### 상품 ─ 자산

```
[Product] 1 ────────── * [Holding]
```

- **다중도**: 1:N (하나의 상품이 여러 계좌 보유 자산에 연결 가능)
- **관계 유형**: 참조 (Association)
- **비즈니스 규칙**:
  - 자산은 반드시 하나의 상품을 참조해야 함
  - 상품이 삭제/중단되더라도 기존 자산/스냅샷은 기록을 유지

---

### 계좌 그룹 ─ 계좌

```
[AccountGroup] * ────────── * [Account]
```

- **다중도**: M:N (계좌 그룹 여러 개가 같은 계좌를 포함 가능)
- **관계 유형**: 참조 (Association)
- **비즈니스 규칙**:
  - 계좌 그룹은 0개 이상의 계좌를 포함할 수 있음
  - 계좌는 여러 계좌 그룹에 포함될 수 있음
  - 그룹에서 계좌가 제거되어도 계좌 자체는 삭제되지 않음 (Cascade 없음)
  - 서로 다른 금융사의 계좌를 같은 그룹에 포함 가능

---

### 전체 구조

```
[User] 1 ────────── * [Portfolio]
  |
  | (관리자)
  ↓
  [AccountGroup] * ────────── * [Account]
                                    |
     [Institution] 1 ──────── * [Account] 1 ────────── * [Holding] * ────────── 1 [Product]
       |                        |                        |                      |
     + name: string         + name: string                                  + product_name: string
     + type: string         + type: string                                  + asset_class: string
                            + balance: Money                                + attributes: AssetAttributes

                      (평가금액은 스냅샷·현황에서 관리)
```

**설명**:
- `Portfolio`: 사용자의 전체 자산 집합
- `Institution`: 금융사 (증권사, 은행 등)
- `Account`: 금융사 내 계좌
- `AccountGroup`: 관리자가 정의한 논리적 계좌 그룹 (M:N 관계)
- `Holding`: 계좌 내 개별 자산
- `AssetAttributes`: 자산의 다차원 속성

## 애그리게이트 (Aggregates)

### 포트폴리오 (Portfolio) - Aggregate Root

**개념**: 사용자의 전체 자산 현황을 관리하는 최상위 개념

**구성 요소**:
- 여러 금융사 (Institution)
- 각 금융사의 여러 계좌 (Account)
- 각 계좌의 여러 자산 (Holding)

**책임**:
- 전체 자산의 일관성 보장
- 총 자산 평가액 계산
- 트랜잭션 경계 설정

**불변식**:
- 포트폴리오의 총 평가액 = 모든 자산 평가금액의 합
- 사용자당 하나의 포트폴리오

---

## 값 객체 (Value Objects)

### 금액 (Money)

**속성**:
- 금액 (amount): Decimal
- 통화 (currency): 원화, 달러

**불변식**:
- 금액은 음수일 수 없음 (특정 상황 제외)
- 통화가 다른 금액은 직접 연산 불가

**동일성**: 금액과 통화가 모두 같으면 동일

---

### 자산 속성 (Asset Attributes)

**속성**:
- 투자 지역 (region): 한국, 미국
- 자산 종류 (asset_type): 주식, 채권, 통화, 금, 부동산, 기타
- 화폐 (currency): 원화, 달러
- 투자유형 (investment_type): 직접투자, ETF
- 자산특징 (characteristics): 개별종목, 지수추종, 레버리지 등
- 위험도 (risk_level): 위험, 안전

**불변식**:
- 모든 속성은 사전 정의된 값만 허용
- 일단 설정되면 변경 불가 (불변)

**동일성**: 모든 속성이 같으면 동일

---

## 스냅샷 (Snapshot)

### 포트폴리오 스냅샷 (Portfolio Snapshot)

**개념**: 특정 기준일의 포트폴리오 상태를 불변 기록으로 저장

**유형**:

#### 1. 일반 스냅샷 (Snapshot)
- **생성 시점**: 관리자가 수동 생성 (status = in_progress)
- **입력 방식**: 관리자가 자산별 평가금액을 입력 (부분 입력 가능)
- **확정**: 관리자가 잠금(lock) 버튼 클릭 시 확정 (status = locked)
- **용도**: 특정일 포트폴리오 작업본, 주간/연간 스냅샷의 원본

#### 2. 주간 스냅샷 (Weekly Snapshot)
- **생성 시점**: 토요일에 관리자가 생성 버튼 클릭
- **원본**: 최근 1주일 사이에 확정된 가장 최근 일반 스냅샷 (locked)
- **용도**: 주 단위 자산 변동 추적
- **생성 규칙**: 최근 1주일 내 확정된 일반 스냅샷이 없으면 생성 불가

#### 3. 연간 스냅샷 (Annual Snapshot)
- **생성 시점**: 1월 1일부터 1주일 사이 관리자가 생성 버튼 클릭
- **원본**: 1월 1일에 가장 가까운 날짜에 확정된 일반 스냅샷 (locked)
- **용도**: 연 단위 장기 성과 분석
- **생성 규칙**: 1월 1일 전후 확정된 일반 스냅샷이 없으면 생성 불가

**주요 속성**:
- 기준일 (reference_date): 스냅샷 생성 기준 날짜
- 총 평가액 (total_value): 기준일의 전체 자산 평가액
- 자산 목록 (holdings_snapshot): 각 자산의 상세 정보
- 생성일시 (created_at): 스냅샷 생성 시각
- 수정 가능 기한 (editable_until): 수정 가능 기한 시각
- 상태 (status): in_progress | locked
- 잠금 일시 (locked_at): 잠금 시각 (locked 시 기록)
- 데이터 소스 (data_sources): 자산별 자동/수동/미입력 플래그

**불변식**:
- 동일 기준일에 대해 하나의 스냅샷만 존재 (사용자 + 기준일로 고유)
- 스냅샷의 총 평가액은 자산 목록의 평가액 합계와 일치
- status = locked 이후에는 수정 불가 (editable_until 도과 시 자동 잠금)
- 주간/연간 스냅샷은 기준일의 locked 일반 스냅샷을 원본으로 삼음

**수정 정책**:
- 일반 스냅샷: editable_until 이전에 자산별 부분 입력/수정 가능, 이후 자동 잠금 또는 관리자 잠금
- 주간 스냅샷: 다음 주간 스냅샷 생성 시점까지 수정 가능 (최대 1주)
- 연간 스냅샷: 생성 후 1주일간 수정 가능
- 수정 가능 기한 경과 후에는 과거 기록으로 확정되어 수정 불가

**관계**:
```
[User] 1 ────────── * [PortfolioSnapshot]
                          |
                          | (포함)
                          ↓
                    [HoldingSnapshot] *
```

**생명주기**:
- 일반 스냅샷 생성: 관리자가 수동 생성 (status = in_progress)
- 일반 스냅샷 입력: 관리자가 자산별 평가금액을 부분/전체 입력
- 일반 스냅샷 잠금: 관리자가 잠금 버튼 클릭 시 확정 (status = locked)
- 주간 스냅샷 생성: 토요일에 관리자가 버튼 클릭 (최근 1주일 내 locked 일반 스냅샷 필요)
- 연간 스냅샷 생성: 1월 1~7일 사이 관리자가 버튼 클릭 (1/1 전후 locked 일반 스냅샷 필요)
- 수정: 각 스냅샷의 editable_until 내에서만 가능
- 삭제: 관리자 권한 필요

## 비즈니스 규칙

### 1. 계층 구조 규칙
- 금융사 없이 계좌 존재 불가
- 계좌 없이 자산 존재 불가
- 삭제 시 하위 항목 Cascade 처리
- 관리자만 금융사, 계좌, 자산 추가/수정/삭제 가능

### 2. 평가액 계산 규칙
- 계좌 잔액 = 해당 계좌의 모든 자산 평가금액 합계
- 포트폴리오 총액 = 모든 계좌 잔액 합계
- 계좌 그룹 총액 = 그룹 내 모든 계좌 잔액 합계
- 평가금액은 스냅샷에서만 관리하며 Holding에는 저장하지 않음
- 자산 현황: 사용자의 가장 최근 일반 스냅샷을 조회한 현재 포트폴리오 상태

### 3. 스냅샷 규칙
- 일반 스냅샷: 관리자가 수동 생성(status = in_progress), 자산별 평가금액 입력 가능
- 일반 스냅샷 잠금: 관리자가 잠금 버튼 클릭 시 확정; 잠금 후 불변
- 주간 스냅샷: 토요일에 관리자가 버튼 클릭하여 생성, 최근 1주일 내 locked 일반 스냅샷을 원본으로 사용
- 연간 스냅샷: 1월 1~7일 사이 관리자가 버튼 클릭하여 생성, 1/1에 가장 가까운 locked 일반 스냅샷을 원본으로 사용
- 같은 기준일에 동일 사용자의 스냅샷은 하나만 존재
- 숨김 처리된 자산: 기준일 이후 생성되는 스냅샷에서 제외
- 과거 스냅샷: 삭제/숨김과 무관하게 당시 상태를 보존
- 수정 가능 기한:
  - 주간 스냅샷: 다음 주간 스냅샷 생성 시점까지 수정 가능 (최대 1주)
  - 연간 스냅샷: 생성 후 1주일간 수정 가능
- 수정 가능 기한 경과 후 과거 기록으로 확정 (불변)
- 관리자만 스냅샷 삭제 가능

### 5. 삭제 규칙 (자산)
- 자산 삭제는 2단계로 수행: 숨김 → 완전 삭제
- 숨김 상태의 자산은 일반 사용자 조회/집계에서 제외
- 완전 삭제는 관리자만 수행 가능하며 감사 로그를 남김
- 삭제가 스냅샷에 미치는 영향: 기존 스냅샷은 불변, 신규 스냅샷은 숨김/삭제 상태를 반영

### 6. 자산군 규칙
- 자산군(Asset Class)은 사전 정의된 카테고리: 주식, 채권, 통화, 금, 부동산, 가상자산, 기타자산
- 각 자산(Holding)은 반드시 하나의 자산군에 속해야 함
- 자산군은 시스템에서 관리하며 사용자가 변경 불가

### 7. 계좌 그룹 규칙
- 관리자만 계좌 그룹 생성/수정/삭제 가능
- 계좌 그룹은 M:N 관계 (하나의 계좌가 여러 그룹에 포함 가능)
- 서로 다른 금융사의 계좌를 같은 그룹에 포함 가능
- 계좌 그룹에서 계좌 제거는 그룹 관계만 삭제 (계좌 자체는 유지)
- 사용자가 계좌 그룹별로 정렬된 조회 가능
